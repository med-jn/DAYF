# الضيف — وكيل صوتي لبثوث تيك توك (أندرويد)

## كيف يعمل
- يلتقط **صوت الهاتف الداخلي** (صوت البث) عبر AudioPlaybackCapture ويرسله إلى Gemini Live مع لقطات من الشاشة.
- يشغّل ردّ الوكيل عبر **منفذ السماعة 3.5mm**؛ ما دام الصوت الخارج يدخل الميكروفون عندك (كما جرّبت) فسيسمعه البث.
- الذاكرة والقواعد والمعرفة كلها في Supabase.
- فقاعة عائمة 🎙 للتحكم الفوري.

## الخطوات
1. **Supabase**: أنشئ مشروعاً مجانياً ← SQL Editor ← الصق `supabase/schema.sql` ← Run.
   ثم من Table Editor عدّل صف `agent_config` (الاسم، الأسماء البديلة، اللهجة، الشخصية…) وأضف صفوف `rules` و`knowledge`.
   خذ من Project Settings ← API: الـ URL ومفتاح anon (أو publishable).
2. **GitHub**: أنشئ مستودعاً (مثلاً `dayf-android`) وارفع محتويات هذا المجلد كما هي (مع مجلد `.github`).
   تبويب **Actions** ← Build APK ← Run workflow. بعد دقائق يظهر **Release** فيه ملف `app-debug.apk` حمّله على الهاتف وثبّته.
3. **في التطبيق**: أدخل المفاتيح، ثم الخطوات 1 و2 و3، ثم «4) اختبار الاتصال».
4. **اختبر الالتقاط أولاً**: الزر «5) اختبار التقاط الصوت فقط»، افتح تيك توك وادخل بثاً أنت ضيف فيه،
   وانظر شريط «التقاط الصوت» في الفقاعة. إن تحرّك مع أصوات البث فكل شيء تمام. إن بقي صفراً فتيك توك يمنع التقاط صوته.
5. **للتشغيل الفعلي**: «▶ تشغيل الوكيل» (وسماعة 3.5mm موصولة بالوصلة التي جرّبتها).

## معايرة اكتشاف الحالة (ضيف / مايك)
- الاكتشاف الأساسي بالرؤية (لقطة الشاشة تُحلَّل كل ~6 ثوانٍ) ويحتاج «اسم حسابك الظاهر» في الإعدادات.
- الدقة الأعلى بقراءة نصوص الواجهة: أثناء كونك ضيفاً اضغط «📋 نسخ الشاشة» في الفقاعة ثم الصقه في المحادثة،
  وسنملأ `keywords` في `agent_config` بالكلمات الحقيقية.
- ما دامت الحالة مجهولة فالوكيل **صامت** (إلا إن غيّرت `allow_unknown_state`). ويمكنك فرضها يدوياً من الفقاعة.

## أمان
- المفاتيح تُخزَّن على الهاتف فقط ولا تُرفع. لا ترفع أي ملف `.env` إلى GitHub.
- مفتاح Supabase المستعمل (anon) محدود بسياسات RLS في الـ SQL: قراءة الإعدادات والمعرفة، وإضافة الذاكرة والسجلات.
